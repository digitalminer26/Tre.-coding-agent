# MCP audit — cycle 3 (gpt-6.1-sol)

Round 3 of the MCP audit/remediation loop. The cycle-2 report (`.mcp-audit-cycle2.md`)
found 3 new issues (readable-pipe errors, post-violation dispatch, the busy-restart
drain gap) plus 4 incomplete cycle-1 branches; all were fixed. This round re-audited
the remediated change set with THREE independent gpt-6.1-sol passes (raw reports +
prompts in `.tre/audit-cycle3/`, gitignored), each followed by a fix pass and a
re-audit.

## Findings and resolutions

### Audit 1 (r1) — minor: the compaction drain test did not exercise production wiring
`test/restart.test.ts` supplied the turn promise through a test stand-in; it never
invoked the production tracking/cancellation path, so reverting manual `/compact`
to an untracked fire-and-forget operation would have left the test green.
**Resolution:** extracted the shared active-work tracker into `src/tui/active-work.ts`
(`ActiveWork`, identity-guarded so an older operation's completion cannot clear a
newer one), wired BOTH runs and manual `/compact` through it, and added a
driver-level test that tracks a compaction-shaped operation with its real
AbortController and asserts abort → deferred persistence → teardown → spawn.

### Audit 2 (r2) — minor: restart could proceed while replacement work is active
`runRestartSequence` drained the captured promise but never re-checked for a NEWER
operation that took the active slot in the settle gap (a run or compaction started
while the old one was finishing); it could tear down MCP and spawn while the
replacement's persistence was unfinished. Reproduced with the compiled production
helpers. Current keyboard/Telegram `restartInFlight` guards made it unreachable from
the TUI entry points, but the helper contract was wrong.
**Resolution:** one overall deadline across every operation that becomes active
during the drain — the loop aborts, waits, and re-reads the slot, breaking only on
`null` (cleared) or the same already-settled promise, and returning
`drain-timeout` (no teardown, no spawn) when a replacement is still live past the
deadline. Added settled-then-replaced and stuck-then-replaced regression tests.

### Audit 3 (r3) — no findings
Verified: loop termination in every case (slot cleared → break; same settled
promise → break; repeated instantly-settled replacements are bounded by the
deadline check, which does not depend on a timer callback); the `next === drain`
identity break is correct (a native promise cannot become pending again); zero
remaining budget is safe (a zero-delay timer still lets an already-settled promise
win the race); the one real stuck-work path (e.g. `read` on a writerless FIFO,
which ignores abort) ends at the 5s bound with the documented
"press Ctrl+C twice to force-exit" message — intended bounded-failure behavior, not
a defect.

## Verdict

No actionable defects remain in the audited change set. All three audited
findings (2 minor, 0 major) are fixed with regression tests. Final state:
build clean, quality gate clean, 216/216 MCP + restart tests pass.

## Verified OK (no action)

- Abort precedes bounded drain; a rejected turn counts as settled; the drain
  timer is cleared on every path (verified by a child-process exit-time test).
- `ActiveWork` identity-guarded clearing: older completions cannot clear newer
  slots; rejected operations clear their slot.
- Manual compaction is tracked through its persistence (`compactNow` awaits the
  session append before settling), so an in-flight append stays inside the
  restart barrier.
- RFC 3629 second-byte restrictions (E0 A0–BF, ED 80–9F, F0 90–BF, F4 80–8F) are
  checked on PRESENT bytes before classifying a suffix as incomplete: impossible
  prefixes are malformed (replacement char), not silently dropped; trailing ASCII
  survives; genuinely incomplete valid suffixes are suppressed; the exposed view
  is capped to the tail's byte length.
- Startup cannot resolve "ready" after a terminal failure or close/kill landed in
  the same chunk as the final tools/list response.
- A stdout read error fails the server in-band; a stderr read error is recorded
  (byte-bounded) and not terminal; a stdout close without EOF is transport death.
- Legacy `initialize` version validation: real calendar date, not a modern-era
  version (equality included), nothing newer than the client revision.

## Environmental note (not a code defect)

The full unit suite cannot go green in this sandbox: the repo-local `tre.json`
lists `~/kubeconfigs` as an extra root, which the kernel sandbox cannot
`realpath` (EPERM), so the CLI's fail-closed `validateExtraRoot` refuses startup
(exit 2) for the 33 CLI/Telegram-driver tests that spawn the CLI from the repo.
Confirmed pre-existing: the identical failures occur on the clean baseline with
the audit changes stashed. The scoped MCP + restart suites (216 tests) do not
spawn the CLI and are the reliable signal here.
