**1.** No legitimate placement shares `repoCommon`: if git resolves a common dir equal to ours, git itself has placed the anchor inside one of our worktrees (main, linked, renamed-but-intact, or the `.git`/worktree admin dir), which §5 forbids. `wtRoot = repoRoot`, a dir inside the main checkout when `repoRoot` is a linked worktree, and a dir inside a sibling linked worktree are all correctly refused; a genuine sibling/separate-mount dir probes a documented negative (search exhausts at `/`) and passes. The rule is therefore correct *as long as the negative really means "search exhausted"* (see finding).

**2.** No previously-working flow breaks: a fresh outside `wtRoot` probes negative and is created; `prune` still uses `isWithin` (only consumer, so not dead) and `remove` never used the deleted containment list; `repoToplevel` is still the provisioner's `repoRoot` (cwd + returned provenance), so nothing is unused — only two comments still say "containment" (stale doc, no behavior).

**3.** REJECT — one confirmed containment bypass (F1). The "documented negative → outside any repo" branch conflates git's honest search-exhausted message with git's hard error for a broken gitfile, which the module's own F4 comment says must never masquerade as a negative.

## Findings

**F1 (confirmed, containment bypass — `open()` placement gate).** `NEGATIVE_MARKERS` matches any stderr containing `"not a git repository"`, so git's dead-gitlink error `fatal: not a git repository: <path>` (exit 128, emitted when `.git` is a *file* pointing at a missing gitdir — e.g. a moved/copied worktree dir, or a dir whose admin entry was pruned) makes `gitVerify` return `null`, and `open()` treats the anchor as "outside any repo" and mkdirs. Repro: repo `/r`; `mkdir /r/sub`; `writeFile('/r/sub/.git','gitdir: /nonexistent\n')`; `open({repoRoot:'/r', wtRoot:'/r/sub/wt'})` creates `/r/sub/wt` instead of `wt-inside-repo` — then `ensureTaskWorktree` provisions a worktree nested inside our own checkout (same bypass against a *foreign* repo yields `wt-in-other-repo` violation). Fix: only the search-exhausted wording (`not a git repository (or any of the parent directories)`) is a pass; the `not a git repository: <path>`/broken-gitlink form must raise `git-failed` (or be refused), never "outside".

**F2 (minor, error contract).** `nearestExisting` can return a non-directory (e.g. a linked worktree's `.git` *file*): `open({repoRoot: linkedWt, wtRoot: join(linkedWt,'.git','x')})` execs git with `cwd` = a regular file → `ENOTDIR`, not a documented negative → `git-failed` instead of `wt-inside-repo`. No mutation occurs (safe), but the placement gate should `stat` the anchor and refuse/report deterministically.
