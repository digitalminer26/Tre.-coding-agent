## 1. HIGH — list opened during a pending span is not tracked

**Probe appended to the valid base document:**

```markdown
a `
- item
  <!--
§99999
-->
`
```

The list marker interrupts the first paragraph. The comment opens inside the list item, but the unindented `§99999` leaves that item and is visible CommonMark text. It must be flagged.

**Executed repro:**

```text
$ node scripts/contract-check.mjs docs/audits/probes-r21-c15/lost-list.md
exit 0
stderr: empty
```

The pending-span branch consumes `- item` without updating `listStack`. Consequently, the comment is recorded as root-owned rather than list-owned, and the dedented visible ref is masked. The same result occurred with `1. item` in `lost-ordered.md`.

**Minimal fix:** Process container-opening and paragraph-interruption transitions before treating a line as pending-span content. In particular, terminate the old span and update the list stack when a list marker interrupts its paragraph; then record the comment’s actual owning list depth.

## 2. HIGH — nested list opened during a pending span loses comment ownership

**Probe:**

```markdown
- outer
  a `
  - item
    <!--
  §99999
  -->
  `
```

The nested list interrupts the paragraph. The comment belongs to the nested item; the ref dedents out of that item and is visible in the outer item.

**Executed repro:**

```text
$ node scripts/contract-check.mjs docs/audits/probes-r21-c15/lost-nested.md
exit 0
stderr: empty
```

This is the same missed-transition defect as finding 1, but demonstrates that retaining an *existing* outer list stack is insufficient: the newly opened inner item must also be recorded. The fix is the same.
