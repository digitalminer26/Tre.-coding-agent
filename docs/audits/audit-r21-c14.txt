## 1. LOW — Pending code span prevents a type-2 comment block from opening

**Repro**, appended after the valid base document:

```markdown
a `
<!--
§99999
`
-->
```

**Expected:** Both commonmark.js and markdown-it render the paragraph as `<p>a `</p>`, followed by an HTML comment block containing `§99999`. The comment block interrupts the paragraph, so its opener must terminate the pending inline-span state. The ref is exempt.

**Actual:**

```text
$ node scripts/contract-check.mjs docs/audits/probes-r21-c14/comment-interrupt.md
exit 1
... line 6005: §99999
```

Both renderers were run on the full fixture; their output ends with:

```html
<p>a `</p>
<!--
§99999
`
-->
```

**Minimal fix:** Before treating a line as pending-span content, recognize a valid type-2 comment-block opener in its container context, clear `spanRun`, and process the comment normally. Preserve the existing fail-closed rules for unsupported containers.
