**Q1 — Concurrency / TOCTOU.** `run`/`resume` snapshot records, state, and probes, then `await` before `children.set`, so two callers can pass the fence on the same snapshot and both spawn. `children` is keyed by session, so a second spawn overwrites the first entry and orphans a live worker. No mutex exists; a realistic P9 issuing parallel per-task retries reaches all of these.
1. High, `attempt.ts:run/resume/fenceOrThrow/spawnAttempt` — concurrent `run+run` on one task compute the same `nextAttemptId`, both pass the fence, both append intent, two workers share one session and one attemptId. Fix: instance-wide (or per-session) async mutex covering allocation→fence→intent→spawn→register→resolve as one critical section.
2. High, `attempt.ts:spawnAttempt children.set` — concurrent spawns on the same session overwrite the map entry; the loser is unstoppable via `stop`, invisible to `hasLiveChildren`. Fix: same mutex plus reserve the session synchronously (pending placeholder) before the first `await`; fail-fast on duplicate reservation.
3. High, `attempt.ts:fenceOrThrow` — fence observes pre-intent records, so an in-flight intent from a concurrent caller is invisible (stale read → duplicate spawn). Fix: covered by the same mutex; re-read records inside the lock.
4. Medium, `attempt.ts:stop` — double `stop` both see `!exited`, both signal and both await `exitPromise` (double SIGTERM/SIGKILL, inconsistent `escalated`). Fix: same mutex or per-entry stopping flag.
5. Medium, `attempt.ts:confirmStopped vs run` — confirm's live/probe checks race a concurrent spawn; evidence is checked before the resolving append. Fix: same mutex around confirm's check-and-append.

**Q2 — stop() completeness.** `terminate` returns after the direct child's `exit` event; a detached group whose leader exits while a grandchild survives still counts as `stopped:true, escalated:false`. That is not waitpid-class evidence for a group and directly breaks the I1 claim in the header. A single `kill(-pgid,0)` miss is also insufficient (racy re-check).
1. High, `attempt.ts:terminate/stop` — leader-exits-grandchild-survives reports `stopped:true, escalated:false` while the group writes the session. Fix: after child exit, loop `kill(-pgid,0)` until ESRCH (bounded); if still present, SIGKILL the group, re-poll, set `escalated:true` when group-KILL was needed; resolve only on group-gone or timeout-failure.

**Q3 — Ownership derivation (§14.5) and cross-task claims.** `analyze` filters records to `task.taskId` and probes only `state.tasks[task.taskId]`, so foreign-task durable claims on the same session file are never examined. The only cross-task gate is the in-memory live-child check, which does not survive restart.
1. High, `attempt.ts:analyze/fenceOrThrow` — (a) foreign unresolved intent on same session: not caught, fresh spawn proceeds → two writers. Fix: join the fence on session across all taskIds: scan all attempt records and all `state.tasks` rows for matching `sessionPath`/`session`, probe matching foreign hints, refuse unless all disproven.
2. High, same location — (b) foreign spawned-ok same session with no hint row: not caught. Fix: same as above.
3. High, same location — (c) foreign spawned-ok same session with hint row under the foreign taskId: not caught (`row` lookup misses it). Fix: same as above.
4. PASS: same-instance foreign live child is fenced (tested).

**Q4 — Restart reconcile and attempt history.** After restart `live` is always `undefined` and the hint holds one attemptId, so every non-latest `spawnOutcome:"ok"` view gets no probe and hits the `!probe → park` branch. The supervisor must then `confirmStopped` every historical attempt on every restart before any new spawn.
1. High, `attempt.ts:fenceOrThrow spawned loop + analyze` — N historical `ok` attempts mean N manual confirms per restart (unbounded, growing); each confirm rewrites `ok→failed`, falsifying history. Fix: bound the liveness gate to the latest attempt per (task, session) tuple (or latest per task); treat older `ok` tuples superseded by a later durable tuple as closed, not live-gated.

**Q5 — confirmStopped() and state-hint integrity.** `confirmStopped` unconditionally rewrites the task's hint row to the confirmed (possibly stale) attemptId with `pid` cleared. It also accepts `latest.spawnOutcome==="ok"`, appending a `failed` record over a resolved tuple.
