## Findings

1. **LOW — Tabs in list indentation prevent a real comment block from being masked**

   Appended fixture (`tabcontent.md`; `→` denotes one literal tab):

   ```text
   - item
     →<!--
     →§99999
     →-->

   end
   ```

   Both commonmark.js and markdown-it render the three tabbed lines as a type-2 HTML block inside the list item; `§99999` is inside the comment and should be exempt.

   Executed:

   ```text
   node scripts/contract-check.mjs docs/audits/probes-r21-c10/tabcontent.md
   exit 1
   stderr: ... line 6005: §99999
   ```

   `atBlockStart` consumes only literal spaces in its leading-prefix loop, so it rejects the tab even though, after consuming the item’s content column, the comment begins within the permitted indentation.

   **Minimal fix:** consume the existing list-container prefix by visual column using tab stops and partial-tab semantics, then test the remaining indentation relative to that container.

2. **LOW — Indented code beginning on a list-marker line is scanned as prose**

   Appended fixture (`listcode.md`):

   ```markdown
   -     x <!--
         §99999
         end

   end
   ```

   Both reference renderers put `x <!--`, `§99999`, and `end` in an indented code block inside the item. Under the checker’s code-block masking policy, the ref is exempt.

   Executed:

   ```text
   node scripts/contract-check.mjs docs/audits/probes-r21-c10/listcode.md
   exit 1
   stderr: ... line 6004: §99999
   ```

   `trackList` correctly reduces the item content column to 2 for five spaces after the marker, but the indented-code start check runs **before** `trackList` and does not recognize code beginning on that marker line.

   **Minimal fix:** recognize the marker-padding-over-four case when processing the marker line, and enter list-owned indented-code state with the item content column plus four as its continuation floor.

3. **LOW — Text after a closed type-2 block opener on the same line is scanned**

   Appended fixture (`same-line.md`):

   ```markdown
   <!-- hidden --> §99999

   end
   ```

   Both reference renderers emit the entire first line as a type-2 HTML block. The ref is in raw HTML-block content, not a rendered paragraph; the checker’s HTML-block policy exempts it.

   Executed:

   ```text
   node scripts/contract-check.mjs docs/audits/probes-r21-c10/same-line.md
   exit 1
   stderr: ... line 6003: §99999
   ```

   The closed-comment branch masks only through `-->` and resumes scanning the line, even when the opener started a type-2 block.

   **Minimal fix:** distinguish block-start comments from inline comments before handling a same-line closer; for a type-2 block, mask the entire opener line.
