**Q1 (contract coherence).** The "fence before ANY caller-visible decision" promise holds on the refiled-only path (`assertClaimHeld` then snapshot proof) and on replay (`assertClaimHeld` before return). It fails on the ACKED return: after the append fsync, only `assertSameInode(provenOn, identityOfPath)` runs, and no claim re-check occurs before `return { status: "acked" }`. Constructor, zero-record `appendUnit(() => [])`, and two same-process instances all behave as documented, since `pidAlive` on our own pid keeps a live sibling's claim unswept. Replay of a pre-cycle-4 layout is not covered: a legacy regular file at `<log>.lock` makes `mkdirSync` return EEXIST, and `openSync("<log>.lock/claim-…")` then fails with ENOTDIR, which is not in the retry set and escapes as a raw Error on every call. `make()` mutating its returned array is harmless because `incoming` is consumed once, before any mutation.

**Q2 (test-name integrity).** "V-g13: a pass appending TWO records issues exactly ONE append fsync" counts only the `"append"` label on a cold instance, whose first pass also runs `log-file`, `log-dir`, `marker-file`, `marker-dir`, and `lock-acquire` syncs. It passes with those extra syncs, so the name's "one fsync" overclaims. "the claim exists during the unit and is gone after every exit path" checks only ack and one refusal (`S5ReplayIntegrityError`); the `S5LockLostError`, I/O-throw, and sync-failure exits are not asserted there, so "every" is not enforced. "the whole unit is atomic" checks a single divergent-id case, not the general claim.

**Q3.** Not CLEAN. The two scenarios I tried hardest to break were (1) a claim removed between the append fsync and the acked return, and (2) an old-protocol file at `<log>.lock`.

**Findings**

1. **Acked return is not claim-fenced (contract violation).** Scenario: a sync spy removes the registry entry when `label === "append"`. The fsync succeeds, `assertSameInode` passes (the log file is intact), and `appendUnit` returns `status: "acked"` even though our claim is gone. The header promises "OUR entry must still exist… else S5LockLostError is thrown fail-stop (nothing written / no decision returned)". Fix: call `assertClaimHeld(held)` before the acked return.

2. **Pre-cycle-4 lock file wedges every append with a raw errno.** Scenario: `<log>.lock` exists as a regular file from an older protocol. `mkdirSync` throws EEXIST and is tolerated. `openSync("<log>.lock/claim-…", "wx")` then throws ENOTDIR, which is not ENOENT/EEXIST, so the error escapes as a generic "S5 lock acquire failed" with no `S5LockBusyError` and no recovery path. The sweep never runs because `readdirSync` on a file fails. The header documents "pre-cycle-6 legacy format" only for names inside the registry, not for a legacy file at the registry path itself. Fix: detect a non-directory at `regPath` and either migrate or refuse with a documented class.
