## Findings

1. **HIGH — Nested ordered marker is not tracked, so a comment survives beyond its list item.**

   Appended to the valid base document:

   ```markdown
   - a
     - 2. <!--
       §99999
       -->
   ```

   CommonMark opens an outer list, a nested bullet item, and an ordered item starting at 2. The comment belongs to that ordered item. The `§99999` line is dedented outside the ordered item, so it renders as visible text in the enclosing bullet item.

   Executed repro:

   ```text
   $ node scripts/contract-check.mjs docs/audits/probes-r21-c8/nested1.md
   exit 0
   stderr: <empty>
   ```

   `commonmark.js` renders the relevant portion as:

   ```html
   <li>
   <ol start="2">
   <li>
   <!--
   </li>
   </ol>
   §99999
   --&gt;</li>
   ```

   **Cause and minimal fix:** `trackList` applies the `paraOpen` / ordered-start-not-1 interruption rule to *every* marker in a same-line chain. Here it refuses the inner `2.` even though the preceding `- ` opened a fresh item context. `atBlockStart` accepts that inner marker, but the comment is owned by the shallower tracked list. Apply the interruption restriction only where an existing paragraph is actually being interrupted, and keep list tracking and block-start recognition consistent. Add a regression covering the dedent.

2. **LOW — Tab-indented list comment is reported as a live ref.**

   Appended fixture, with each `→` representing one literal tab byte:

   ```text
   - x
   →<!--
   →§99999
   →-->
   ```

   CommonMark expands the tab to column 4 and renders the three lines as a comment block inside the list item; the ref is hidden.

   Executed repro:

   ```text
   $ node scripts/contract-check.mjs docs/audits/probes-r21-c8/tabs.md
   exit 1
   stderr: contract-check: FAIL C9 ... — line 6005: §99999
   ```

   **Minimal fix:** Have the block-start prefix scan consume tabs using absolute CommonMark tab stops and the active list content column, rather than accepting only literal spaces in its indentation loop. Retain the existing container-boundary checks.

## Requested gate and interaction checks

- **Q1 — Container prefixes:** The nested ordered-list chain above demonstrates a masking error, although the immediate cause is inconsistent list ownership rather than the prefix loop alone. The ordinary three-level nested-list and tab-after-marker fixtures passed. Blockquote comment fixtures failed closed with the checker’s explicit unsupported-container diagnostic.
- **Q2 — After a closer:** `closer.md` (`- a` followed by `    <!-- a --> b <!-- c`) reports `§99999`; CommonMark renders it visible. The second opener follows text on the same line, so it is not a new block start; this repro is not a HIGH or an overstrict finding. I did not construct a case where the second opener on that same line is a block start. The ordered-list fixture `1. item` / `  <!--` passed; `> <!--` failed closed as unsupported.
- **Q3 — Marker plus content:** `inline.md` (`- x <!--`) reported the ref; `spaced.md` (`-     x <!--`) reported it inside rendered code. The latter is overstrict, but not the requested comment-state masking mismatch.
- **Q4 — Degenerate opener:** `<!--> x <!--` followed by `§99999` was reported, as required.
- **Q5 — Spans:** The three closed-span variants and the unclosed-backtick-plus-blank-line fixture reported the visible ref.
- **Q6 — EOF and block interactions:** The unclosed block-comment EOF fixture exited 1 with an unclosed-comment issue. Setext and frontmatter-shaped fixtures with closed comments passed. This does not establish that every EOF state is safe.
